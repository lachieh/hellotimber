## Entry, operators and Options

Menu 9 opens a single `0` above `Options`, without a calculator-screen indicator. The display
uses up to three right-aligned small-face lines: first operand, operator, second operand.
Painter coordinates must be measured from imported goldens before Task 5 closes. The planning
layout has `Options` at y 40. It is not proof of every baseline or cursor coordinate.

Digits append and leading zeros collapse. Entry accepts nine magnitude characters, counting
`.`. Extra characters are ignored. `#` on a fresh calculator entry gives `0.`; a second point
is ignored. A minus cannot be typed directly. C removes the last character, then leaves `0`.
Another C on `0` leaves to the Calculator carousel, restarting its icon. Scroll keys do not edit
calculator operands. Evidence: `entry/**`, `exit/**` and their canonical key sequences.

`*` cycles `+`, `-`, `*`, `/`, then `+`, without a multi-tap timeout. Captures spaced three
seconds apart still cycle. A digit after the operator starts the second operand. `*` after a
second operand evaluates and starts `+` on the displayed result. C deletes the second operand,
then the operator, then the first operand. Evidence: `operators/**`, `operator-slow/**`.

Options is a rows list opening on its first entry with soft key `OK`. Its indicator is the
position within this list, not the kernel's menu `9`.

| State                           | Options in order                                                                |
| ------------------------------- | ------------------------------------------------------------------------------- |
| Number or result                | Equals, Add, Subtract, Multiply, Divide, In domestic, In foreign, Exchange rate |
| Operator without second operand | Add, Subtract, Multiply, Divide                                                 |
| Operator with second operand    | Equals, Add, Subtract, Multiply, Divide                                         |

Equals with both operands shows the result alone. Equals without an operator changes nothing.
Choosing an operator replaces it when there is no second operand; with a second operand it
calculates first and then sets the chosen operator. A digit after a result starts a new number;
`#` starts `0.`; `*` continues from the result. C leaves Options without changing the arithmetic
state. There is no Square, Square root or Change sign. Evidence: `options/**`, `choose/**`.

Numeric, `*` and `#` keys in Options leave the calculator for standby number entry with soft
key `Call`. They do not select numbered Options rows. See the later contract gate below.
Evidence: `sound/keys-options-{0…9,star,hash}/**` and independent
`sound/options-dtmf-confirm-{0,1}/**`.

## Decimal results and the corrected R criterion

Results fit nine magnitude characters, including `.`, excluding the leading minus.
`-123456789`, `-999999999`, `-0.3333333` and `-0.0000001` are valid ten-character strings.
Ten integer digits overflow, including a rounding carry to ten digits. Fractions round half
away from zero; trailing fractional zeros and a trailing point disappear. Rounded zero is `0`.
The next operation uses the displayed result, not hidden extra precision.

| Representable calculation           | Captured result          | Evidence under `results/`                                 |
| ----------------------------------- | ------------------------ | --------------------------------------------------------- |
| `0.1 + 0.2`                         | `0.3`                    | `0.1+0.2.png`                                             |
| `1 / 3`, `2 / 3`                    | `0.3333333`, `0.6666667` | `1d3.png`, `2d3.png`                                      |
| `(1 / 3) * 3`, `(2 / 3) * 3`        | `0.9999999`, `2.0000001` | `1d3x3.png`, `2d3x3.png`                                  |
| `(1 / 3) + (1 / 3)`                 | `0.6666666`              | `1d3+1d3.png`                                             |
| `±24691357 / 2`                     | `±12345679`              | `24691357d2.png`, `-24691357d2.png`                       |
| `±0.0000001 / 2`                    | `±0.0000001`             | `0.0000001d2.png`, `-0.0000001d2.png`                     |
| `±0.0000003 / 2`                    | `±0.0000002`             | `0.0000003d2.png`, `-0.0000003d2.png`                     |
| `9.9999999 + 0.0000001`             | `10`                     | `9.9999999+0.0000001.png`                                 |
| `0 - 99999999`, then subtract `0.5` | `-100000000`             | `-99999999.5.png` (case name describes the unrounded sum) |
| `999999999 + 1`                     | Out of range             | `999999999+1.png`                                         |

The original Task 0 R asks for `0.00000005 * 1`, `-0.00000005 * 1` and
`9.9999999 + 0.00000001`. Those operands cannot be entered within nine magnitude characters.
`results/literal-0.00000005x1.png`, `literal--0.00000005x1.png` and
`literal-9.9999999+0.00000001.png` show the exact requested key sequences truncated by the editor;
the outputs are `0`, `0`, `9.9999999`. Their `-after` companions capture the subsequent state.
These are entry tests. They do not prove arithmetic on the impossible operands.

The corrected criterion keeps literal truncation tests and separately requires the representable
half-rounding cases above. The captured carry to `10` uses `0.0000001`; it is a different sum.
Do not inject impossible operands into the engine or use their captures as pure arithmetic
expectations. Task 0 R remains unticked until the parent reviews the complete original C5/R
checklist against this correction. Exact decimal arithmetic is the planned reproduction design;
the captures do not establish the firmware's internal numeric representation.

## Held keys and notes

Digits, `*` and `#` draw while held and enter once. In `clear-held`, `1` draws at 3746.5 ms
while down from 3700.5 to 4900.7 ms. `*` draws at 5747.8 ms while down from 5700.8 to
6901.0 ms. `#` draws at 7746.1 ms while down from 7701.1 to 8901.2 ms. Release must not
perform the action again.

C first deletes, then clears while held. The two clear redraws are 532.1 and 544.0 ms after
down (`clear-held/{timings,keys}.csv`). They are consistent with about 500 ms plus redraw
latency, but do not establish the exact internal hold timer. The kernel's 800 ms default is
not the observed behavior. C held on `0` exits through the carousel to standby. Validate the
whole press/release timeline before choosing a reproduction timer.

Division by zero shows `Dividing / by zero / not allowed`; overflow shows `Out of range`.
Both use the info icon and restore the pre-action arithmetic state after 2875.4-2906.4 ms.
Equals and an operator choice can trigger a note. A key pressed 500.1 ms into a note dismisses
it: C and ▼ restore unchanged, while a digit also edits the restored operand (`7 / 0` becomes
`7 / 5`; `99999 * 99999` becomes `99999 * 999995`). Held C can continue to standby.
Evidence: `notes/**`, `sound/note-key/**`.

## Exchange rate and persistence

Exchange rate opens two pages with `OK` and indicators `8-1` and `8-2`:
`Foreign unit / expressed in / domestic units` and
`Domestic unit / expressed in / foreign units`. The entry prompt has a pen, `Exchange rate:`,
a box and a large value with roughly 480 ms cursor blink. Virgin Foreign shows `0`; virgin
Domestic is empty. Evidence: `rate/list/**`, `rate/prompt-{foreign,domestic}/**`.

Rate entry is a separate cursor editor. Typed input stops at seven characters, counting `.`,
although a prefilled reciprocal can show nine (`0.6666667`). The first digit replaces the
prefilled value. `#` on virgin Foreign starts `.`; another point is ignored. C can empty the
field, C on empty returns to the rate list, and held C clears. OK on empty or `.` saves zero.

| Cursor input from a typed `123`     | Captured field       | Evidence under `rate/keys/` |
| ----------------------------------- | -------------------- | --------------------------- |
| ▲, `4`                              | `4123`               | `up-digit.png`              |
| ▲, ▲, `4`                           | `1423`               | `up-mid-digit.png`          |
| ▲, ▲, ▲, C                          | `13`                 | `start-c.png`               |
| ▼ from the end                      | cursor on last digit | `down.png`, `down-mid.png`  |
| insertion at seven typed characters | unchanged            | `limit-insert.png`          |

▲ advances and wraps from the end to the start. Cursor deletion is not ordinary calculator
backspace. Use paired blink phases when cursor ink obscures a character. The plan 18 editor
must not be assumed to support these rules.

Saving shows `Rate / saved` with a tick, then returns to the calculator, not the rate list.
`rate/saved` has tick segments 694.1/232.0/523.1 ms; the factory sound recording has
708.1/218.0/538.1 ms. Keep those separate measured timelines.

One directional rate governs conversion. Foreign `1.5` shows Domestic `0.6666667`.
Domestic `3` shows Foreign `0.3333333`, yet `10` In domestic gives `3.3333333` and In foreign
gives `30`. Conversion cannot multiply by the rounded reciprocal. Evidence:
`rate/after/{foreign-1.5-domestic,domestic-3-foreign}.png` and
`convert/domestic-3-10-in-{domestic,foreign}.png`.

Foreign `1.5` survives saveflash and cold boot. Calculator operands reset to `0` after boot
and re-entry. Restore factory settings (6-4, code `12345`, security-code seed) gives rate `1`
in both prompts after either Domestic `2` or Foreign `1.5`. Evidence: `persist/**`, especially
`restore{,-foreign}-run/**` and `restore{,-foreign}-prompt-{foreign,domestic}/**`.

The planned `nokia-os/calculator` version 1 record stores the original rate string and its
`foreign`/`domestic` direction, with a separate factory value of Foreign `1`. This design
reproduces the observations. Physical EEPROM byte encoding remains UNVERIFIED.

## Sound and later contract gates

Factory calculator and rate keys beep at 900 Hz, level `0x9104`, about 140-148 ms.
Options arrows/C/OK also beep. Error notes replace OK's beep with 1750 Hz at `0x9105`:
296.1 ms for Out of range, 288.1 ms for division by zero. Virgin error-triggering OK is silent;
the preceding Options beep remains. `Rate saved` has no extra confirmation tone, but its
triggering OK beeps. Evidence: `sound/{keys,out-of-range,divide-by-zero,divide-by-zero-virgin,
rate-saved,note-key}.events.csv` and `sound/keys-rate-*`.

Options numeric/star/hash transitions instead emit simultaneous DTMF frequencies:

| Key         | Frequencies (Hz)             |
| ----------- | ---------------------------- |
| 1, 2, 3     | 1209+697, 1336+697, 1477+697 |
| 4, 5, 6     | 1209+770, 1336+770, 1477+770 |
| 7, 8, 9     | 1209+852, 1336+852, 1477+852 |
| `*`, 0, `#` | 1209+941, 1336+941, 1477+941 |

`sound/keys-options-*` records all pairs. Independent short-key
`options-dtmf-confirm-{0,1}` recordings confirm both the `Call` LCD and their pairs.
An exploratory held-key recording reached telephony and was discarded after an incorrect
assumption that Options would remain open. It does not establish call-progress behavior.

Plan 22 owns the standby-entry handoff. The parent/shared sound owner must reconcile VISION's
single-frequency `StockSoundEvent` with both simultaneous tones and verify host consumers.
Plan 20 must not invent telephony, flatten DTMF or emit two unrelated single-tone events.
Keep these fixtures `pending:20` until real LCD and sound drivers pass the delivered contracts.
This is a bounded later gate for these scenarios and final completion.

Plan 29 owns text harvesting, note sounds and named timeline registration. Inspect its actual
delivered API before runtime Task 2. Verify text/note/timeline regeneration end to end and
repeat it without changes. No unverified registration filename or API is prescribed here.
Existing `menu/09-calculator.sub` and `sound/note/9` remain pending in their original indexes
until real opening drivers pass. Import new calculator fixtures as `pending:20`, promote only
passing behavioral drivers, and retain placeholder ownership until real node coverage passes.
